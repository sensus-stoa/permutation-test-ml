## Одна строка

Проверяем не «есть ли сигнал», а «насколько необычен результат всей процедуры
поиска относительно конкретной нулевой гипотезы».

## Что здесь есть

- **Часть A.** Данные с заведомо известной линейной зависимостью.
  Тест возвращает малое p. Ожидаемо.
- **Часть B.** Чистый шум, но широкая процедура поиска (много кандидатов,
  выбираем лучший на обучении). Тест возвращает большое p: «открытие» —
  артефакт отбора, а не сигнал.
- **Часть C.** Два независимых случайных блуждания с общим трендом.
  Наивное перемешивание меток разрушает структуру и даёт ложно малое p.
  Это показывает, почему схема перестановок должна сохранять зависимость.

## Нулевая гипотеза (формально)

Пусть `T(D)` — скор, который возвращает вся процедура поиска на данных `D`.

`H0`: распределение `T(X, y)` совпадает с распределением `T(X, π(y))`
для равномерной случайной перестановки `π` — то есть `y` перестановочен
при фиксированном `X` с точки зрения процедуры.

Объект проверки — процедура (поиск + отбор + оценка), а не одна фиксированная
модель. Это соответствует системной нуль-калибровке протокола CV→0
(раздел 0.7, doi:10.5281/zenodo.23599882): вся конвейерная процедура гоняется
на перемешанных метках, и считается частота ложных принятий.

## Запуск

```bash
pip install -r requirements.txt
python src/permutation_test.py
```

Сид фиксирован: `SEED=7`. Время выполнения: несколько секунд.
Зависимости запинены в `requirements.txt` (`numpy`, `scikit-learn`).

## Что воспроизводится

Чистый запуск одной командой. Сид зафиксирован. Все числа в выводе
детерминированы при тех же версиях библиотек.

Одиночный прогон (SEED=7, N_PERM=200):

| Часть | Данные | observed R² | p-value | Интерпретация |
|-------|--------|-------------|---------|----------------|
| A | посаженный линейный сигнал | 0.971 | 0.005 | отклоняем H0, сигнал виден |
| B | чистый шум, выбор лучшего из 78 кандидатов | -0.585 | 0.731 | «лучшая» модель неотличима от случайного отбора |
| C | два независимых случайных блуждания | 0.350 | 0.005 | ложное отклонение: наивное перемешивание разрушило тренд |

## Повторные прогоны: частота ложных срабатываний

Внешний цикл в `experiments/repeated_runs.py` повторяет весь эксперимент
на независимых данных (по 50 прогонов на сценарий, alpha=0.05):

| Сценарий | Отклонений H0 | Доля | 95% CI (Wilson) |
|----------|---------------|------|------------------|
| noise (H0 истинна) | 1/50 | 0.020 | [0.004, 0.105] |
| signal (H0 ложна) | 50/50 | 1.000 | [0.929, 1.000] |
| spurious_trend (H0 истинна, наивное перемешивание) | 36/50 | 0.720 | [0.583, 0.825] |

Чтение таблицы: на чистом шуме тест откалиброван (доля отклонений
согласуется с alpha=0.05). На посаженном сигнале тест имеет мощность.
На зависимых данных наивная схема перемешивания даёт ошибку I рода
порядка 0.7 вместо 0.05 — в 14 раз выше номинала.

Воспроизведение сводки:

```bash
python experiments/repeated_runs.py --runs 50 --n-permutations 200
```

Машиночитаемый вывод пишется в `results/repeated_runs.csv`
(каталог `results/` в .gitignore, файл регенерируется командой выше).

## Чего здесь нет

- Доказательства, что конкретная развёрнутая модель переобучена
- Проверки причинности или бизнес-ценности найденной связи
- Покрытия всех структур зависимости (здесь только общий тренд)
- Корректной сохраняющей структуру нулевой гипотезы для Части C
  (например, дифференцирование рядов или блочный бутстрап)
